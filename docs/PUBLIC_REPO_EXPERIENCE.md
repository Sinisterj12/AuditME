# Public Repo Experience

> Status: coming-soon experience guide. This describes how the public repo should feel before the official alpha is released.

AuditME should look like a serious new agent-workflow product is about to drop, without pretending the installable release has already happened.

## Desired First Impression

A first-time visitor should understand three things quickly:

- AI coding agents are fast, but project truth drifts.
- AuditME is a repo-native control layer for memory, proof, boundaries, and handoff.
- The first alpha is intentionally waiting until the install path and trust model are proven.

The repo should feel active, focused, and close to release-candidate quality.

## Front-Door Checklist

The front door is working when:

- the banner and tagline create immediate recognition
- the first paragraphs explain the problem without buzzword fog
- the current status is honest and easy to find
- the planned command path is visible but clearly not a release announcement
- docs links guide the visitor from story to proof to adoption
- no private repo, relay, customer, or local-machine context is needed

## Suspense Checklist

Suspense is working when the repo shows:

- a clear promise
- a small first product spine
- concrete release gates
- visible prelaunch proof
- public-safe visual identity
- enough restraint to make the product feel trustworthy

Suspense is not working if the repo relies on:

- fake badges
- fake install buttons
- broad roadmap noise
- private screenshots
- unexplained internal terms
- claims that sound like the alpha has already shipped

## Docs Journey

Recommended visitor path:

1. `README.md` for the hook, status, and product promise.
2. `COMING_SOON.md` for the prelaunch story.
3. `docs/FIRST_5_MINUTES.md` for the intended user workflow.
4. `docs/PRODUCTIZATION_PLAN.md` for how AuditME becomes a product.
5. `docs/PRELAUNCH_READINESS.md` for current proof.
6. `docs/RELEASE_PREFLIGHT.md` for official release gates.

## Content Rule

Every public-facing page should strengthen one of these messages:

```text
Agent work needs repo truth.
Proof should beat confidence.
Handoffs should survive chat loss.
The first alpha is small on purpose.
The release waits for proof.
```

If a page does not strengthen one of those messages, it should be simplified or deferred.
